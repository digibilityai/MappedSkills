# Project Rules

## Rule 1 — Evidence Before Certainty
Do not present strategic assumptions as facts.

## Rule 2 — Repository Is Project Memory
Important context must be written to repository documentation, not left only in chat history.

## Rule 3 — Minimum Necessary Context
Read `CONTEXT_INDEX.md` and load only the files relevant to the current task.

## Rule 4 — No Silent Scope Expansion
Do not move into a new project phase without explicit instruction.

## Rule 5 — Preserve Before Replacing
The existing website must be inspected before design or implementation changes are proposed.

## Rule 6 — SEO Equity Is an Asset
Existing URLs, rankings, internal links, backlinks, content, metadata, and indexation must be inventoried before migration.

## Rule 7 — Search Strategy Must Be Researched
No keyword map or content roadmap may be based solely on intuition.

## Rule 8 — AI Visibility Must Be Measured, Not Claimed
No guarantee of ranking or citation across LLMs. Measure observable outcomes using a defined prompt universe and methodology.

## Rule 9 — Content Must Have a Job
Every page or content asset must have a documented purpose: commercial conversion, ranking, citation, authority, education, backlink acquisition, or strategic support.

## Rule 10 — No Commodity Content Factory
Avoid scaled low-value pages, repetitive city pages, thin AI-written blogs, or content generated only to hit keyword counts.

## Rule 11 — Performance Is Architectural
Performance budgets must influence design, animation, fonts, third-party scripts, imagery, and component architecture from the beginning.

## Rule 12 — Conversion Is Architectural
CRO is not a final polishing phase. Visitor intent, CTA hierarchy, trust, forms, and funnels must shape the site before visual design.

## Rule 13 — Accessibility Is a Release Requirement
Target WCAG 2.2 AA unless explicitly revised.

## Rule 14 — Test What You Change
Code changes must be accompanied by relevant testing.

## Rule 15 — Do Not Fake Proof
No invented logos, testimonials, dashboards, rankings, results, revenue claims, benchmarks, or case studies.

## Rule 16 — Human Approval Gates Matter
Strategic direction, visual direction, homepage, service landing pages, and migration-sensitive changes require owner approval.

## Rule 17 — Maintain a Decision Trail
Meaningful approvals and reversals must be recorded in `DECISION_LOG.md`.

## Rule 18 — Prefer Primary Sources
Use official search-engine, platform, standards-body, and first-party documentation where appropriate.

## Rule 19 — Current Guidance Must Be Verified
SEO, AI crawler, structured data, and platform guidance can change; re-check current official documentation at the time of implementation.

## Rule 20 — Stop When Instructed
If a task prompt says STOP after an artifact or audit, do not begin the next phase.
